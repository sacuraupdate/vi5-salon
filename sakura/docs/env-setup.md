# 環境変数の設定手順（SAKURA 用）

このページは、**パスワードや鍵のような秘密の情報を、どこからコピーして、どこに貼るか**を
1つずつ説明したものです。コードの知識は不要です。

---

## はじめに：なぜコードに直接書かないのか

Stripe や Supabase の鍵は、**銀行の暗証番号と同じ**です。
コードに書いてしまうと、GitHub に保存された時点で、その鍵を見た人が
売上を引き出したり、購入者の情報を読んだりできてしまいます。

そのため、鍵は「環境変数」という別の場所に入れます。
**Claude はコードに鍵を一切書いていません。入れる場所だけ用意してあります。**

---

## 3つの環境

| 環境 | どこ | 誰が見るか |
|---|---|---|
| **Development（開発）** | SAKURA のパソコンの中だけ | 自分だけ |
| **Preview（確認）** | 公開前の確認用サイト | 関係者だけ |
| **Production（本番）** | 実際にお客様が見るサイト | 世界中 |

**まずは Development と Production の2つだけで進めて構いません。**
Preview は staging 環境を作るときに追加します。

### Development に入れる場所

`sakura` フォルダの中に **`.env.local`** という名前のファイルを作り、そこに書きます。
このファイルは GitHub に保存されません（`.gitignore` で除外済み）。

### Production に入れる場所

Cloudflare に入れます。ターミナルで次のように打つと、貼り付けを求められます。

```
cd sakura
npx wrangler secret put STRIPE_SECRET_KEY
```

貼り付けて Enter を押すと保存されます。**画面には表示されません**（それが正常です）。

> **例外：** 名前が `NEXT_PUBLIC_` で始まる2つだけは秘密ではないため、
> `wrangler secret` ではなく、**サイトを組み立てる（ビルドする）ときに必要**です。
> `.env.production` というファイルに書いてから `npm run cf:deploy` を実行してください。

## 設定する環境変数の一覧

| 変数名 | 何の値か | どのサービスから | Development | Preview | Production |
|---|---|---|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | サイトのURL | 自分で決める | ✅ | ✅ | ✅ |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | 問い合わせ先メール | 自分で決める | ✅ | ✅ | ✅ |
| `SUPABASE_URL` | データベースのURL | Supabase | ✅ | ✅ | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | データベースの鍵 | Supabase | ✅ | ✅ | ✅ |
| `STRIPE_SECRET_KEY` | 決済の鍵 | Stripe | テスト用 | テスト用 | **本番用** |
| `STRIPE_WEBHOOK_SECRET` | 入金通知の鍵 | Stripe | テスト用 | テスト用 | **本番用** |
| `RESEND_API_KEY` | メール送信の鍵 | Resend | ✅ | ✅ | ✅ |
| `EMAIL_FROM` | 送信元アドレス | 自分で決める | ✅ | ✅ | ✅ |
| `CONTACT_TO_EMAIL` | 問い合わせの届き先 | 自分で決める | ✅ | ✅ | ✅ |
| `SITE_DEMO_MODE` | 確認用ログイン | — | `true` | — | **絶対に設定しない** |
| `ADMIN_DEMO_MODE` | 確認用の管理画面 | — | `true` | — | **絶対に設定しない** |

## ① Supabase（データベース）

### 1-1. まずデータベースの表を作る

1. https://supabase.com を開いてログイン
2. プロジェクトを選ぶ（無ければ「New project」で作る。**リージョンは Tokyo でなく、購入者に近い場所でも構いません**）
3. 左のメニューから **「SQL Editor」** をクリック
4. **「New query」** をクリック
5. `sakura/supabase/migrations/0001_init.sql` の中身を**すべてコピーして貼り付け**
6. 右下の **「Run」** をクリック
7. 「Success. No rows returned」と出れば完了です

### 1-2. `SUPABASE_URL` を取得する

1. 左のメニュー下部の **「Project Settings」**（歯車のアイコン）をクリック
2. **「Data API」** をクリック
3. **「Project URL」** の欄にある `https://xxxxxxxx.supabase.co` をコピー

→ これが `SUPABASE_URL` です。

### 1-3. `SUPABASE_SERVICE_ROLE_KEY` を取得する

1. 同じ「Project Settings」の中の **「API Keys」** をクリック
2. **`service_role`** と書かれた行の「Reveal」を押して表示し、コピー

→ これが `SUPABASE_SERVICE_ROLE_KEY` です。

> ⚠️ **この鍵はデータベースの全権限を持ちます。**
> 誰かに見せたり、チャットに貼ったり、スクリーンショットに写したりしないでください。
> `anon` と書かれたほうの鍵ではありません。間違えないでください。

## ② Stripe（決済）

### 2-1. 商品と価格を作る

**市場ごとに価格が違うため、価格は市場の数だけ作ります。**

1. https://dashboard.stripe.com を開いてログイン
2. 画面右上の **「テスト環境」** のスイッチを**オンにする**（まずはテストから）
3. 左メニューの **「商品カタログ」** →「商品を追加」
4. 名前に `Japanese Salon Standard` と入れる
5. 価格を入力して保存する
6. 保存後、同じ商品の画面で **「別の価格を追加」** を押し、通貨を変えて繰り返す
   - 米ドル（USD）／ 台湾ドル（TWD）／ 韓国ウォン（KRW）／ 日本円（JPY）
   - **通常価格とローンチ価格は、別々の価格として作ってください**（Stripe は金額を後から変えられないため）
7. 作った価格それぞれの **`price_` から始まるID** をコピーしてメモする

→ このIDは Claude に渡してください。コードに設定します（秘密情報ではありません）。

### 2-2. `STRIPE_SECRET_KEY` を取得する

1. 左メニューの **「開発者」** → **「APIキー」**
2. **「シークレットキー」** の「表示」を押してコピー
   - テスト環境なら `sk_test_` で始まります
   - 本番環境なら `sk_live_` で始まります

→ これが `STRIPE_SECRET_KEY` です。

> ⚠️ `pk_` で始まるほう（公開可能キー）ではありません。`sk_` のほうです。

### 2-3. `STRIPE_WEBHOOK_SECRET` を取得する

**これが無いと、お客様が支払っても受講できるようになりません。** 必ず設定してください。

1. 左メニューの **「開発者」** → **「Webhook」**
2. **「エンドポイントを追加」** をクリック
3. 「エンドポイントURL」に次を入力（`＜サイトのURL＞` は自分のドメインに置き換え）

   ```
   ＜サイトのURL＞/api/stripe/webhook
   ```

4. 「リッスンするイベント」で **`checkout.session.completed`** を選ぶ（これ1つで足ります）
5. 保存すると、詳細画面に **「署名シークレット」** が表示されます。「表示」を押してコピー
   - `whsec_` で始まります

→ これが `STRIPE_WEBHOOK_SECRET` です。

> テスト環境と本番環境で**別々の値になります**。切り替えたら必ず取り直してください。

## ③ Resend（メール送信）

### 3-1. 送信するドメインを登録する

1. https://resend.com を開いてログイン
2. 左メニューの **「Domains」** → **「Add Domain」**
3. 自分のドメイン（例：`sakurajapanbeauty.com`）を入力
4. 表示された **DNSレコード**（3〜4行）を、ドメインを買った会社の管理画面に登録する
5. Resend の画面に戻り、緑色の **「Verified」** になるまで待つ（数分〜1時間）

> この手順を飛ばすと、送ったメールが迷惑メールに入ります。必ず行ってください。

### 3-2. `RESEND_API_KEY` を取得する

1. 左メニューの **「API Keys」** → **「Create API Key」**
2. 名前は何でも構いません（例：`sakura-production`）
3. 権限は **「Sending access」** で十分です
4. 表示された `re_` で始まる値をコピー

→ これが `RESEND_API_KEY` です。

> ⚠️ **この値は作成直後の1回しか表示されません。** 閉じる前に必ずコピーしてください。

### 3-3. `EMAIL_FROM` を決める

3-1 で登録したドメインのアドレスにします。形式は次のとおりです。

```
SAKURA JAPAN BEAUTY <no-reply@自分のドメイン>
```

→ これが `EMAIL_FROM` です。登録していないドメインを書くと送信できません。

## ④ 自分で決める値

### `NEXT_PUBLIC_SITE_URL`

サイトのURLです。最後の `/` は付けません。

```
https://自分のドメイン
```

パソコンで確認しているときは `http://localhost:3000` です。

### `NEXT_PUBLIC_SUPPORT_EMAIL` と `CONTACT_TO_EMAIL`

- `NEXT_PUBLIC_SUPPORT_EMAIL` … **お客様に表示される**問い合わせ先（例：`support@自分のドメイン`）
- `CONTACT_TO_EMAIL` … 問い合わせフォームの内容が**実際に届く**アドレス（普段使っているメールで構いません）

同じでも構いません。

---

## 設定が終わったら確認する

1. 管理画面の **「システム状況」** を開く
2. 4項目すべてが緑色の **「設定済み」** になっていれば完了です
3. 赤い「未設定」が残っていれば、そこに何をすればよいか日本語で書いてあります

## 絶対にやってはいけないこと

- ❌ `sk_live_` や `service_role` の鍵を、チャット・メール・スクリーンショットに貼る
- ❌ `SITE_DEMO_MODE` や `ADMIN_DEMO_MODE` を**本番**に設定する
      （設定すると、誰でも管理画面に入れてしまいます）
- ❌ `wrangler.jsonc` に鍵を書く（このファイルは GitHub に保存されます）
- ❌ 鍵を変更したあと、`wrangler secret put` をやり直さずに放置する

鍵が漏れたかもしれないと思ったら、**すぐ各サービスの画面で鍵を作り直してください**。
古い鍵はその場で無効になります。
